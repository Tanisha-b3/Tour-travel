# Plan: Move Wishlist to Backend (Per-User Persistence)

## Context
Currently, wishlist is stored in `localStorage` via `AppContext.jsx`. It is not tied to any user account — if the user clears browser data or switches devices, the wishlist is lost. The user wants:
1. Wishlist persisted in the backend, tied to each logged-in user
2. Wishlist only available when logged in (show login prompt otherwise)

## Approach
Add a `wishlist` array to the User model (array of destination IDs). Create dedicated wishlist API endpoints. Refactor `AppContext` to fetch/persist wishlist via API when a user is logged in, falling back to localStorage when not logged in.

---

## Backend Changes

### 1. Update `Server/models/User.js`
- Add `wishlist: [{ type: Number }]` field (stores destination IDs, which are Numbers in the Destination model)

### 2. Update `Server/repositories/userRepository.js`
- Add `getWishlist(userId)` — return user's wishlist array
- Add `toggleWishlist(userId, destinationId)` — add or remove a destination ID from the wishlist
- Add `clearWishlist(userId)` — empty the wishlist array

### 3. Update `Server/services/authService.js`
- Update `sanitizeUser()` to include `wishlist` in returned user data
- Update `getMe()` to return wishlist along with user info

### 4. Create `Server/controllers/wishlistController.js`
- `getWishlist(req, res)` — returns user's wishlist (array of destination IDs)
- `toggleWishlist(req, res)` — adds/removes a destination ID, returns updated wishlist
- `clearWishlist(req, res)` — clears all wishlist items, returns empty array

### 5. Create `Server/routes/wishlistRoutes.js`
- `GET /api/wishlist` — protected, get user's wishlist
- `POST /api/wishlist/toggle` — protected, toggle a destination (body: `{ destinationId }`)
- `DELETE /api/wishlist` — protected, clear all

### 6. Update `Server/index.js`
- Mount `wishlistRoutes` at `/api/wishlist`

---

## Frontend Changes

### 7. Update `travel-tour/src/services/api.js`
- Add `getWishlist(token)` — GET `/wishlist`
- Add `toggleWishlistAPI(token, destinationId)` — POST `/wishlist/toggle`
- Add `clearWishlistAPI(token)` — DELETE `/wishlist`

### 8. Update `travel-tour/src/context/AppContext.jsx`
- Accept `token` and `user` from `AuthContext` (via props or context)
- When logged in: fetch wishlist from API on mount/login, sync toggles to API
- When logged out: use localStorage as before (guest wishlist)
- On login: merge localStorage wishlist into backend wishlist
- On logout: clear backend wishlist (already saved), reset to empty

### 9. Update `travel-tour/src/components/DestinationCard.jsx`
- When user is not logged in and they click the heart, open the AuthModal instead of toggling

### 10. Update `travel-tour/src/main.jsx`
- Adjust provider nesting if needed (AuthContext needs to be accessible to AppContext)

## Data Flow
1. **Logged out**: Wishlist in localStorage (guest mode), heart works normally
2. **Login**: localStorage wishlist merged into backend, API becomes source of truth
3. **Logged in**: All wishlist operations hit the API, state synced from API responses
4. **Logout**: Backend wishlist persists (already saved), frontend resets to empty
